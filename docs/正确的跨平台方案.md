## 技术架构对比

### Electron架构（Web套壳）
```
┌─────────────────────────────┐
│   Electron应用 (77-300MB)   │
├─────────────────────────────┤
│  Chromium浏览器 (~100MB)    │
│  ├─ HTML/CSS/JavaScript     │
│  └─ React前端               │
├─────────────────────────────┤
│  Node.js运行时 (~50MB)      │
│  ├─ Express服务器           │
│  ├─ node_modules (~100MB)   │
│  └─ 调用系统chafa           │
└─────────────────────────────┘
```

**问题：**
- 打包整个浏览器和运行时
- 三层架构（浏览器→Node→系统）
- 资源浪费，效率低

### Tauri架构（真原生）
```
┌─────────────────────────────┐
│    Tauri应用 (3-5MB)        │
├─────────────────────────────┤
│  系统WebView (共享，0MB)    │
│  ├─ HTML/CSS/JavaScript     │
│  └─ React前端               │
├─────────────────────────────┤
│  Rust原生后端 (~3MB)        │
│  └─ 直接调用系统chafa       │
└─────────────────────────────┘
```

**优势：**
- 使用系统浏览器引擎（已安装）
- 两层架构（WebView→Rust）
- 原生性能，极小体积

### 代码改动

#### 后端（JavaScript → Rust）

**之前（Express服务器）：**
```javascript
// server.js
app.post('/api/convert', upload.single('image'), (req, res) => {
  const options = req.body;
  const chafa = spawn('chafa', buildArgs(options));
  // ...处理输出
});
```

**之后（Tauri Rust）：**
```rust
// src-tauri/src/main.rs
#[tauri::command]
fn convert_image(image_path: String, options: ChafaOptions) -> Result<String, String> {
    let mut cmd = Command::new("chafa");
    // ...构建参数
    cmd.output() // 直接返回
}
```

#### 前端（fetch → invoke）

**之前（HTTP API）：**
```javascript
const response = await fetch('/api/convert', {
  method: 'POST',
  body: formData
});
```

**之后（Tauri）：**
```javascript
import { invoke } from '@tauri-apps/api/tauri';

const result = await invoke('convert_image', {
  imagePath: path,
  options: options
});
```

## 🐛 问题1: 背景色空字符串导致转换失败

### 问题描述
```
chafa: Unrecognized background color ''
```

加载图片后无法转换，错误提示为"无法识别的背景色：空字符串"。

### 原因分析
前端传递的 `bg` 和 `fg` 参数为空字符串 `""`，Rust后端直接传递给chafa命令：
```bash
chafa --bg "" --fg "" image.png
```

Chafa无法识别空字符串作为颜色值，导致转换失败。

### 修复方案
**文件**: `src-tauri/src/main.rs`

**修改前**:
```rust
if let Some(bg) = options.bg {
    cmd.arg("--bg").arg(bg);
}

if let Some(fg) = options.fg {
    cmd.arg("--fg").arg(fg);
}
```

**修改后**:
```rust
if let Some(bg) = options.bg {
    if !bg.is_empty() {  // ✅ 检查是否为空
        cmd.arg("--bg").arg(bg);
    }
}

if let Some(fg) = options.fg {
    if !fg.is_empty() {  // ✅ 检查是否为空
        cmd.arg("--fg").arg(fg);
    }
}
```

### 验证
```bash
# 现在只在有值时才传递参数
chafa -c 256 -s 80x24 image.png  # ✅ 正确，不包含 --bg ""
```

## 🎨 问题2: 下拉菜单白底白字

### 问题描述
下拉菜单的选项文字为白色，背景也是白色，导致无法看清内容。

![问题截图](screenshot.png)

### 原因分析
TailwindCSS 只对 `<select>` 元素应用了样式，但没有对 `<option>` 子元素设置暗色主题，导致 option 使用系统默认的白色背景。

### 修复方案
**文件**: `src/index.css`

**添加样式**:
```css
/* 美化下拉菜单 */
select {
  appearance: none;
  -webkit-appearance: none;
  -moz-appearance: none;
  background-image: url("data:image/svg+xml...");  /* 自定义下拉箭头 */
  background-repeat: no-repeat;
  background-position: right 0.7rem center;
  background-size: 1.2em;
  padding-right: 2.5rem;
}

/* ✅ option 暗色主题 */
select option {
  background-color: #374151;  /* 暗灰色背景 */
  color: #f3f4f6;             /* 浅灰色文字 */
  padding: 8px 12px;
}

/* ✅ hover/选中状态 */
select option:hover,
select option:focus,
select option:checked {
  background-color: #4b5563 !important;
  color: #ffffff !important;
}

/* ✅ 高亮选中项 */
select:focus option:checked {
  background-color: #3b82f6 !important;
  background: linear-gradient(135deg, #3b82f6, #2563eb) !important;
}
```

### 视觉效果
- ✅ 暗灰色背景 (#374151)
- ✅ 白色文字 (#f3f4f6)
- ✅ hover时加深背景 (#4b5563)
- ✅ 选中项蓝色高亮 (#3b82f6)

## 🔍 技术细节

### 为什么会有空字符串？

前端代码中，bg和fg的初始值设置为空字符串：
```javascript
const [options, setOptions] = useState({
  // ...
  bg: '',  // ← 空字符串
  fg: '',  // ← 空字符串
  // ...
});
```

这是合理的默认值（表示使用终端默认颜色），但需要在传递给chafa前过滤掉。

### 为什么option需要!important？

某些浏览器（尤其是基于WebKit的）对 `<option>` 元素的样式支持有限，可能会被系统默认样式覆盖。使用 `!important` 确保自定义样式优先级最高。
